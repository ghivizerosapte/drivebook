# DriveBook — заметки для Claude Code

Полная архитектура и правила — в `AGENTS.md`. Здесь только то, что чаще всего нужно
под рукой: как запустить и как работать над проектом.

## Как запустить (полная последовательность)

Всегда начинай с явного `cd` в корень — относительный `cd api` без корня падает.

```bash
cd ~/projects/drivebook

# 1. Поднять БД (Postgres 16 в docker, host-порт 5433)
docker compose up -d db

# 2. Первый раз — установить зависимости (создаёт api/.venv)
make install

# 3. Миграции + сид (сид читает DRIVEBOOK_SUPERVISOR_* из .env)
make migrate
make seed

# 4. Запустить API (uvicorn, http://127.0.0.1:8100, --reload)
make run
```

Проверки после запуска:
- API docs — http://127.0.0.1:8100/docs
- Лендинг (`/`) — http://127.0.0.1:8100/
- Book — http://127.0.0.1:8100/book
- Admin — http://127.0.0.1:8100/admin/

API запущен с `--reload` — правки кода подхватываются сами. Полный перезапуск нужен только при
смене `.env`/зависимостей или если reload завис: `pkill -f uvicorn`, затем `make run` из корня.

Порты: API `8100`, Postgres `5433→5432`. `.env` обязателен для сид-аккаунта супервизора
(см. `.env.example`), в git не коммитится.

## Как работать (качество важнее скорости)

- Стадии в `PLAN.md` — последовательные, не пропускай критерии готовности (hard-rule 6).
- Один этап = один коммит (hard-rule 7); «готово» только с доказательством: вывод команды,
  k6-summary или скриншот (hard-rule 8).
- После каждого вертикального среза — стоп, покажи diff, жди подтверждения; следующий пункт
  плана сам не начинай.
- Перед нетривиальной задачей — короткое резюме понимания + план, потом код (`/catchup`
  для входа в контекст).
- Гонки бронирования: DB UNIQUE + транзакционный claim, не app-locks (hard-rule 3).
- Обновляй `PROGRESS.md` по мере закрытия этапов — на нём держится преемственность сессий.
